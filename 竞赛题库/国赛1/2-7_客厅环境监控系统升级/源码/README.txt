环境监控(客厅环境监控系统升级) 竞赛任务 2-7 源码
=====================================================

一、运行方法
------------
1) 安装依赖(Python 3.11):
   pip install requests pillow

2) 启动程序:
   python 环境监控.py

   首次运行时若 images/ 目录下的图片素材不存在, 程序会自动调用
   make_images.py 生成(也可单独执行 python make_images.py 预生成)。

二、文件清单
------------
环境监控.py    主程序("环境监控", 1000x640 主界面)
nle_cloud.py   云服务系统 RESTful API 客户端(登录/取数/下发指令, 复用模块)
make_images.py 图片素材生成工具(PIL 绘制 u0/u1 背景、电视画面、风扇图标)
KRoom.txt      参数配置文件(服务器、账号、ApiTag、控制阈值等, 键 = 值)
images/        图片素材目录(运行时自动生成)

三、KRoom.txt 参数说明
----------------------
server_url      云服务系统地址(默认 https://api.nlecloud.com)
username        云服务平台登录用户名
password        云服务平台登录密码
mode            运行模式: cloud=真实云服务 / demo=演示模拟
tag_temp        温度传感器标识(ApiTag)
tag_hum         湿度传感器标识(ApiTag)
tag_light       光照传感器标识(ApiTag)
tag_body        人体红外传感器标识(ApiTag)
tag_fan         风扇执行器标识(ApiTag)
tag_light_on    常亮指示灯-白 执行器标识(ApiTag)
refresh_second  数据自动刷新间隔(秒, 默认 3)
light_threshold 光照阈值(默认 100, 光照<阈值判为"关灯")
temp_threshold  温度阈值(默认 27, 温度>=阈值强制开启风扇)

按实际工位设备修改 ApiTag 后重启程序生效。

四、控制逻辑说明
----------------
1. 温湿度(四输入) / 光照(zigbee) / 人体红外(zigbee):
   通过云服务系统 fetch_sensor 读取并同步刷新显示。
2. 人体红外: 有人 → "有人"; 无人 → "无人"。
3. 空调逻辑:
   - 有人: 自动开启风扇 → 电视显示彩色画面(tv_on.jpg)。
   - 无人: 自动关闭风扇; 点击风扇图片可手动关闭 → 电视同步黑屏(tv_off.jpg)。
   - 温度 >= 27℃: 开启风扇; < 27℃: 关闭风扇
     (温度是最高优先的独立规则; 无人时可被手动关闭覆盖)。
4. 灯光背景:
   - 光照 < 100      → 显示室内关灯背景 u0.jpg, 常亮指示灯-白 On。
   - 光照 >= 100     → 显示室内开灯背景 u1.jpg, 常亮指示灯-白 Off。
5. 执行器同步:
   每个刷新周期将 风扇(开/关) 与 常亮指示灯(On/Off) 指令通过
   send_command 下发到云服务系统, 与实训工位设备状态同步。
6. 演示模式(mode=demo):
   无需硬件即可验证界面与逻辑——温度在25~28℃波动、湿度55~65%RH、
   光照围绕100lux切换、人体红外随机有人/无人。

五、界面操作
------------
- 顶部: 模式(cloud/demo)、服务器、用户名、密码输入框 + "登录"按钮 + 连接状态。
- 左下: "室内场景"画布——背景图随光照切换, 画面含风扇(转动动画)与电视。
- 右下: "数据监测"表格(温度/湿度/光照度/红外对射/常亮指示灯/风扇/电视)
        + "立即刷新"按钮; 数据按 refresh_second 秒自动刷新。
- 点击场景中风扇图标可手动开关(无人时手动关闭风扇)。
